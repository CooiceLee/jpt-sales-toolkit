# JPT Sales Toolkit v0.8+ 功能模块规划

## 当前基线

v0.9.0-internal 已具备：

- 数据复盘：只读经营复盘、风险 Lead、高价值 Lead、权限隔离。
- 出差规划：候选客户、地图联动、计划保存、Stop 重排、路线预览/保存、拜访执行、拜访结果回填、Markdown/CSV 导出。
- 稳定化：Trip Plan / Stop 乐观锁、Stop 删除版本检查、Trip 冲突自动刷新、Trip Planner 地图实例清理、关键操作按钮 loading。
- 坐标治理：Coordinate Review 支持 Needs Review / Missing / Verified 分队列、搜索、地址解析选点、国家字段后端规范化、坐标修改审计和坐标保存冲突提示。
- 数据治理：导入预检、基础批量修复 API、国家/区域规范化、导入前后快照已完成基础版。
- 服务结构：ReviewService 保留 API 门面，已拆出 ReviewAnalysisService、ReviewMapService、TripPlanService，并下沉 CountryService、VisibilityService、ReviewUtils。
- 试运行收口：README、current runbook、启动脚本文案和统一验证脚本已对齐 v0.9 基线。

后续开发应先围绕试运行反馈增强实际工作流，再做较大的分析和自动化能力。

## v0.8 试运行稳定化

目标：让 v0.8 能可靠支撑真实团队试用。

- Bug 收集台账：按模块、账号、步骤、期望、实际、严重级别记录。
- 地图与坐标质量：补“坐标缺失/坐标近似/国家级 fallback”的集中修复入口，支持邮件地址粘贴后解析到地图。状态：已完成基础版。
- Trip Planner 易用性：地图实例清理、按钮 loading、路线预览和保存的状态提示。状态：已完成基础版。
- 并发保护：为 `trip_plans` 和 `trip_plan_stops` 增加 `row_version` 乐观锁。状态：已完成基础版。
- 服务拆分：把 `ReviewService` 拆成 `AnalysisService`、`TripPlanService`、`MapService`。状态：基础版已完成，后续可继续下沉共享 helper。
- 验证闭环：新增 `scripts/validate_v08.sh`，统一跑语法、编译和核心回归。状态：已完成基础版。

验收：

- 团队能连续试用一周，不出现数据损坏或权限串数据。
- 关键操作失败时有明确提示，且不留下半写入状态。

## v0.9 拜访执行

目标：把“计划”延伸到“现场拜访执行和回访闭环”。

- 拜访模式：按日期显示当天客户、联系人、地址、Lead 摘要、拜访目的。
- 结果模板：客户需求、竞争对手、预算、决策人、下一步行动、样品/报价需求。
- 自动任务：保存 `Follow-up Needed` 时可生成下一步跟进任务。
- 附件沉淀：拜访照片、名片、会议纪要、客户资料附件关联到 Lead。
- 导出增强：按天导出行程单和拜访报告。

状态：v0.9.0 已完成基础版。

验收：

- 拜访后不需要再手工回忆整理，关键结论能沉淀到 Lead Activity 和任务中。

## v1.0 管理驾驶舱

目标：让管理层能按区域、人员、产品线做经营判断。

- Pipeline Forecast：按阶段、金额、预计成交时间做预测。
- Owner Performance：销售跟进频率、逾期、报价、赢单、丢单口径统一。
- Region/Product Review：区域和产品维度的增长、转化、风险。
- 多币种归一：增加基础汇率配置，复盘和候选评分使用统一基准币种。
- Review Brief 增强：生成更适合会议复盘的摘要和行动建议。

验收：

- Leader 能用系统直接开周/月度复盘会，而不是再导 Excel 二次整理。

## v1.1 数据交换与治理

目标：降低历史数据迁移和长期维护成本。

- 导入预检：重复客户、缺字段、非法枚举、坐标异常、金额/币种缺失。
- 批量修复：客户国家/区域、Owner、坐标、产品分类、应用场景。
- 数据快照：关键版本发布前后自动备份、可比较差异。
- 审计增强：重要字段变更、导入/恢复、计划导出记录可追踪。

状态：导入预检、坐标审计、国家/区域规范化、基础批量修复 API、导入快照比较已提前进入 v0.9.0；更完整的治理工作台留到 v1.1。

验收：

- 批量导入不会污染主数据，发现问题能回溯和修复。

## 建议顺序

1. v0.8 试运行稳定化。
2. v0.9 拜访执行。
3. v1.0 管理驾驶舱。
4. v1.1 数据交换与治理。

当前不建议优先接实时交通、机票、酒店或复杂路线优化 API。原因是这些能力依赖外部服务、费用和 API key，且会先放大坐标质量问题。应等真实出差规划流程跑通后再评估接入。
