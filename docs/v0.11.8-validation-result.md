## 本版 Tech 任务包验收口径

以下项目是必须验证的业务契约，不代表当前已经通过：

1. Leader 选择启用中的精确 Tech 账号，导出 `.jpttask`；该文件是当前 Leader 终端上该 Tech 全部未归档分配任务的完整快照，不是增量包。
2. 指定 Tech 在独立“Tech Task Packages / 技术任务包”页签预检和导入；Sales、非目标 Tech、其他组织和普通 JSON 入口均不能接收。
3. Tech 只读取完成任务必需的最小客户/需求上下文，并在售前/样品或售后任务中更新允许的状态和结果字段；包内不含报价、金额、PO、输单原因、联系人或附件文件。
4. Tech 导出 `.jptresult`，原 Leader 预检来源、接收账号、任务归属和基础快照后再合并；同一结果字段双方改成不同值时整包阻断，不同字段可合并。
5. 新完整快照缺失旧任务时，只有 Tech 没有未导出更改，或结果已导出且导出后未再修改，才允许带撤回警告归档本地任务；否则整包阻断。
6. 改派、归档、旧快照、同包 ID 异内容和来源基线不一致均阻断；重复导入同一成功包保持幂等，不产生任务副本或重复改写。
7. 首版任务包只有内容校验和精确接收账号校验，没有设备数字签名；只通过团队批准的可信内部渠道点对点传递。
8. 首次迁移和后续任务包往返前先创建完整备份；增量 schema 迁移不得删除或覆盖原客户、Lead、售前/样品、售后、附件、账号或授权数据。
