## 本版解决的问题

### 根治 v0.12.0 的三个阻塞缺陷

| 缺陷 | 根因 | 处理 |
|---|---|---|
| 设了停留时间仍报"行程超时" | 交通段与客户拜访共用工作日分配器（跳过周末），且交通耗时按 `ceil(小时/4)` 折算 | 交通改走日历槽位；耗时改为按经过时间 `ceil(小时/12)`，集中在 `travel_calendar_half_days` |
| 无法添加停靠点，反复提示"放弃更改" | `TripVisitDraft` 是四个草稿状态里唯一没有放弃出口的，被 14 处调用点拦死，切换计划时 guard 在 reset 之前拦截，只能重启应用 | 改为可确认放弃并继续，并在提示中点名受影响客户；自动触发的预览保持非破坏性 |
| 机场到客户之间没有独立行程段 | 机场无处安放 | 机场成为**航班段的属性**（schema 7），只在该段为航班时展开为 `A→起飞机场（地面）/ 机场→机场（航班）/ 落地机场→B（地面）` |

### 机场模型（本版核心）

- 机场属于「停靠点→停靠点」的连接，**不是停靠点**——作为停靠点会被自动排序打乱，v0.12.1 开发过程中已实测证伪该做法。
- 默认为空：未设置机场时该段仍显示为单段航班，不产生 0 公里废段。
- 只能通过位置搜索设置，**界面不出现经纬度输入**；契约层强制「名称与坐标必须成对」。
- 每端可设停留时长（0.5 天粒度），支持"提前一晚到外地机场"。
- 展开逻辑集中在 `trip_flight_expansion.py`，预览、日程与 XLSX/HTML/ICS 导出共用同一实现。
- 跨重算存活：`saved_airports()` 按 leg_key 回填，**不要求锁定该段**。

### 其他修复

- 起终点必填，不再退化为首/末客户点而产生 0 公里假行程段。
- `select_mode` 无合适方式时返回 `other`，不再返回自己刚判定不适用的方式。
- `other` 交通方式的零时长漏洞封堵（契约层与引擎层两处）；前端改为先校验后写草稿。
- 行程失效时显示原因与「重新预览路线」入口，不再只留空白日程；九种失效原因补齐中文。
- 拜访执行卡片显示实际填写的**拜访议题**，而非系统自动写入的默认标签。
- 保存拜访准备后自动关闭编辑器并刷新卡片。
- 地理编码改为中文优先；机场搜索采用多形态查询合并并按机场类型排序。
- 页面重构：影响排期的「计划」与「候选客户」固定在右列；中列自上而下为地图、每日行程、拜访执行、行程与交通段。
- 地图客户点常驻显示序号与拜访日期。

## 已知限制

1. **地图底图标注语言无法统一为中文**：CARTO/OpenStreetMap 瓦片为图片，文字烧录在图内。需更换瓦片服务商，属外部依赖变更，记为技术债。
2. **部分机场别名搜不到**：公共 Nominatim 未收录「宝安机场」等别名，需输入「深圳机场」或城市名。提示文案已引导。
3. **`auth_service._store_password` 在凭据行已存在时只更新 `users` 表**，而登录读取 `user_credentials`，导致应用内改密码不生效、`needs_rehash` 自动升级无法落库。属 P1 认证正确性问题，**不在本版范围**，未修改。
4. 重排导致 `A→B` 不再相邻时，该段已保存的机场失效——不静默丢弃，给出明确 warning。
