# JPT Sales Toolkit v0.13.3-internal 验证证据账本

日期：2026-09-11

性质：**功能与可靠性候选**（`feature/anchor-planning` 一线的成果），在 `v0.13.2-internal` 的安全热修之上。
状态 `UNSIGNED-INTERNAL` 团队内测 / Draft Pre-release。**尚未分发**：是否发给团队由团队负责人决定。

## 这一版相对 0.13.2 多了什么

本轮独立审计与自主开发修好的产品缺陷（每一项都有回归与变异验证）：

| # | 缺陷 | 现在的行为 |
|---|---|---|
| 1 | 读不到硬件地址时设备指纹会随机化，用户被迫反复重新激活 | 固定路径读取；读不到就明确报错，不再编造身份 |
| 2 | 读不到设备标识时前端丢掉原因，直接落到登录框，输完密码才被拒 | 启动页直说"读不到这台电脑的设备标识"，附上程序给的原话，并说明换授权文件没用 |
| 3 | 两家同名公司只有先建的那家会出现在"查找已有客户"里 | 同名客户全部列出，靠城市/国家区分 |
| 4 | 回流包里的空值会清掉本地导出后才填的字段，事前毫无提示 | 预检逐字段列出"本地有值、文件里是空的，导入会清空"（**清空本身仍是既有契约，没有改成自动保留**） |
| 5 | 授权接口参数校验失败会把整个请求体回显，明文带出 password 与签发口令 | 校验错误只回字段与原因，不回值 |
| 6 | 2500 行列表渲染要 3.4 秒（翻译观察器逐节点写文档语言并全文档查询） | 同条件 462 ms；跟进队列 2669 → 312 ms；保存跟进并刷新 5891 → 478 ms |
| 7 | 窄窗口/125% 缩放时面板「保存/取消」被挤出可视区且滚不到 | 标签栏改一行横向滚动，页脚始终在面板内 |
| 8 | 对话框第一次打开焦点不进去；Escape 关不掉对话框 | 首次打开焦点落在第一个字段；Escape 等同于该对话框自己的取消（登录与激活框故意不可 Escape） |
| 9 | Windows 便携安装脚本打印写死的旧版本号；两个 Windows 脚本是 LF 换行 | 从随包 `app\VERSION` 读版本；两个脚本统一 CRLF |

还包含：本轮新增的《团队自助验收清单》离线页、团队升级与回退说明、授权链路操作脚本与验收表。

## 不包含什么

- 不改数据模型（仍是 schema 15）、不改权限规则、不改文件格式合同。
- 不含 macOS Intel 与 Linux 构建。
- 第二台设备的正式激活、真实设备的原生安装与覆盖升级**都没有做**，见下表 Pending。

## 升级与分发

- 从 0.13.1 / 0.13.2 覆盖升级不触发数据库迁移（同为 schema 15）；从更早版本升级会在写入前自动生成并验证 `pre_upgrade` 备份。
- 升级前请先按《团队升级操作与回退说明》做一次备份；**旧版程序读不了升级后的库，回退必须程序与备份一起退**。
- 未做原生安装验证之前，不得把本版描述为"团队升级已验证"或"可以安全分发"。
