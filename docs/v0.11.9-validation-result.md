## 补丁业务口径

本版修复 Tech 账号已看到售前/样品或售后任务卡片，但左侧导航仍显示 0 的状态刷新链路。导航计数保持窄口径，不扩展 Tech 对 Leader/Sales 仪表盘的访问权限：

- “售前 / 样品管理”和“售后”分别统计当前 Tech 账号负责的有效工作量。
- 只纳入状态为 `Open / In Progress`，并且任务、Lead、客户均未归档的记录。
- 按 Lead 去重；一个 Lead 有多项有效任务时，左侧只计 1。
- 页面“全部任务”可同时展示已完成或已取消任务，所以页面任务总数可以大于左侧数字。
- 任务包导入、状态保存和模块刷新后应按同一口径重新读取两个数字。
- Tech 售后卡片只按当前账号获准读取的本人售后任务派生状态；其他 Tech 的 Lead 全局售后状态不再形成幽灵卡片。
- Leader / Sales 的售后导航数字同样只统计 `Open / In Progress`，不再把 `Resolved / Closed` 误算为活动工作量。

## 数据保护边界

- `v0.11.8 schema 3 → v0.11.9 schema 3` 不改变 schema；覆盖升级前必须人工创建完整备份，正常情况下不应新增 `pre_upgrade` 迁移包。
- 安装和卸载不得删除用户数据目录；账号、设备授权、附件和业务数据库必须原位保留。
- 旧 schema 兼容迁移仍须保留既有自动 `pre_upgrade`、失败恢复和二次启动幂等门禁。
