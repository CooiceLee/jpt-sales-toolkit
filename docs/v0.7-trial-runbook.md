# JPT Sales Toolkit v0.7 试运行说明

## 试运行目标

v0.7 在 v0.6 销售漏斗基础上新增两个管理模块：

- `Data Review`：数据复盘，只读分析现有 Lead、成交、跟进和区域数据。
- `Trip Planner`：出差规划，从候选客户生成拜访计划，支持保存、排序、结果回填和导出。

本轮试运行重点不是重新验证所有 v0.6 CRUD，而是确认 v0.7 是否能帮助 Leader 和 Sales 做复盘与拜访决策。

## 启动方式

继续使用一键局域网启动文件：

```text
Start JPT LAN Test Server.command
```

启动后访问：

```text
http://<测试服务器局域网IP>:8000
```

如果刚更新过代码，请先停止旧服务窗口，再重新运行启动文件，确保前端缓存版本和后端新 API 都加载成功。

## Data Review 测试流程

### Leader

1. 登录 `leader01`。
2. 打开 `Data Review`。
3. 切换时间范围：`All time`、`This month`、`Last month`、`This quarter`、`Custom`。
4. 切换 Region 和 Stage 筛选。
5. 检查 Summary Cards、Review Brief、Stage Breakdown、Owner Performance、Region Performance、Risk Leads、High Value Open Leads 是否同步变化。
6. 点击风险 Lead 或高价值 Lead 的编号，确认能打开对应 Lead 详情。

### Sales

1. 登录 `sales01`。
2. 打开 `Data Review`。
3. 确认只看到自己负责或协作的数据。
4. 与 Leader 视角对比，确认总数不应相同，除非测试数据全部属于该 Sales。

### 重点观察

- 筛选后数字是否和列表直觉一致。
- Win Rate、Won Value、Pipeline Value 是否明显异常。
- Risk Leads 是否能暴露长期未跟进、逾期跟进或高价值未成交 Lead。
- 页面加载失败时是否有可理解的错误提示，而不是空白。

## Trip Planner 测试流程

### 创建计划

1. 登录 `leader01`。
2. 打开 `Trip Planner`。
3. 选择 Region 或 Stage 筛选候选客户。
4. 点击 `New plan` 创建计划。
5. 在候选列表中点击 `Add`，添加至少 3 个客户。
6. 检查右侧 `Selected Stops` 是否显示客户、城市、Lead 编号和拜访目的。

### 候选客户和地图

1. 点击候选客户的 `Map`。
2. 确认地图定位到对应客户。
3. 添加客户后，确认地图点位高亮。
4. 点击 `Load more`，确认候选列表可以继续加载，且已有计划不丢失。

### Stop 顺序调整

1. 在 `Selected Stops` 中点击 `Up` / `Down`。
2. 确认首项不能上移，末项不能下移。
3. 调整后刷新页面或重新选择计划，确认顺序仍然保留。
4. 删除一个中间 Stop，确认剩余序号自动变成连续的 `1, 2, 3...`。

### 行程生成

1. 在计划区域填写 Start Date、Origin、Origin lat/lng、Destination、Destination lat/lng。
2. 选择交通方式：`Auto transport`、`Drive`、`Ground public` 或 `Flight`。
3. 勾选 `Skip weekends`，并在 Holidays 中填写一个测试节假日，例如 `2026-05-12`。
4. 在每个 Stop 中填写预计停留天数。
5. 点击 `Preview route`，检查右侧显示预览结束日期、工作日数、交通天数和总距离，但刷新或重新选择计划后不应落库。
6. Holidays 中输入一个无效日期，例如 `bad-date`，确认 warning 可见且有效日期仍参与计算。
7. 点击 `Save route`。
8. 检查每个 Stop 是否生成开始日期、结束日期和上一段交通信息。
9. 检查地图是否显示当前计划路线折线。
10. 输入越界经纬度，例如 `91` 或 `181`，确认后端拒绝保存或预览。

### 拜访结果回填

1. 对某个 Stop 设置结果为 `Visited` 或 `Follow-up Needed`。
2. 填写 Result Notes。
3. 点击 `Save stop`。
4. 打开该 Stop 对应 Lead，检查 Activity 中是否出现 `Trip visit` 记录。
5. 修改 Result Notes 后再次保存，确认同一条回填 Activity 被更新，而不是重复生成多条。

### 导出

1. 点击 `Markdown` 导出。
2. 点击 `CSV` 导出。
3. 检查导出文件是否包含：计划名称、客户、城市、国家、Lead 编号、阶段、金额、拜访目的、结果和备注。
4. 如果字段内容以 `= + - @` 开头，CSV 中应被安全转义，不应被表格软件当成公式执行。

## 权限测试

### Leader

- 应能查看所有候选客户和所有计划。
- 应能创建计划并添加任意可见客户。

### Sales

- 只应看到自己负责或协作的客户/Lead。
- 不应看到其他 Sales 的私有候选客户。
- 创建计划时 owner 应落到当前 Sales，不能伪造为其他 owner。

### Tech

- 不应通过 v0.7 模块绕过原有业务权限。
- 如看到与自己无关的业务 Lead，应记录为 P1 权限问题。

## v0.7 验收标准

- Data Review 为只读，不改变任何业务数据。
- Leader 与 Sales 的数据权限口径正确。
- Trip Planner 能创建计划、添加客户、调整顺序、删除 Stop。
- 拜访结果能回填到 Lead Activity。
- Markdown / CSV 导出可用。
- 页面加载失败时有提示，不出现大面积空白。

## v0.8 已处理项

- `trip_plans` / `trip_plan_stops` 已加入 `row_version` 乐观锁，旧版本提交会返回 409。
- Trip Planner 对 409 冲突会给出刷新重试提示，并自动加载最新计划。
- Stop 删除已加入 `row_version` 检查，避免删除覆盖他人刚保存的 Stop 修改。
- 路线预览不做版本检查，不写库；路线保存才检查 Plan 版本。
- Trip Planner 切换到其他模块时会主动 `remove()` Leaflet 地图实例。
- Trip Planner 的路线预览/保存、Stop 保存、顺序调整和删除会在请求期间禁用按钮，降低重复提交风险。
- Coordinate Review / 地图弹窗的坐标修正支持粘贴客户邮件里的地址，点击 `Find on map` 后定位到地图，再确认保存为人工锁定坐标；国家码会在保存时尽量转成系统配置中的国家名称。
