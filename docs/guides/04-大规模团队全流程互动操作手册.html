1. 安装、首次启动与升级

只关闭浏览器页面不等于退出 JPT；覆盖安装前必须从左下角用户菜单选择“退出 JPT”。

Gate A

Windows 10 / 11 x64

  1. 确认文件名包含 Windows-x64 和 UNSIGNED-INTERNAL。
  2. 双击 Setup；若 SmartScreen 提示，先核对来源和哈希，再选择“更多信息 → 仍要运行”。
  3. 按向导完成，不自行改变用户数据目录。
  4. 从“开始”菜单打开 JPT；不要运行旧解压目录副本。
  5. 浏览器应打开本机 127.0.0.1，标题栏显示 v0.11.8-internal。

macOS Apple Silicon / Intel

  1.  → 关于本机，确认芯片；选择 arm64 或 Intel DMG。
  2. 打开 DMG，把 App 拖入“应用程序”；升级时选择替换。
  3. 推出 JPT 磁盘映像，不能直接运行 DMG 内 App。
  4. 从“应用程序”打开；未签名提示时右键 App → 打开，并再次确认。
  5. 标题栏确认 v0.11.8-internal。
升级后没有重新建号是正常的。程序文件与用户数据分离。Windows 数据在 %LOCALAPPDATA%\JPT Sales Toolkit\data；macOS 数据在 ~/Library/Application Support/JPT Sales Toolkit/data。不要删除数据目录来刷新界面。

2. 账号、设备申请和角色

安装包不按角色区分；Leader / Sales / Tech 由设备绑定授权决定，每名成员默认绑定一台电脑，授权固定 90 天。

Gate A / C
成员选择“加入现有团队”并生成 .jptreq
Leader核对成员、角色、设备并签发 .jptauth
双通道授权文件与 16 位验证码分开发送
成员导入授权，设置至少 8 位本地密码并登录

全新团队首位 Leader

  1. 选择“建立新团队”。
  2. 设置用户名和本地密码。
  3. 设置至少 12 位签发器口令；无法找回，不写入数据库。
  4. 系统建立签发密钥并授权当前设备。
  5. 立即创建完整备份，口令与备份分开保存。

换机、丢失或离职

  • 新电脑重新生成申请，由 Leader 重新签发。
  • 旧授权成为历史，不应复制旧授权到新电脑。
  • 当前离线模式不承诺设备丢失后立即远程停用。
  • 发现姓名、角色或设备不匹配时整体停止，不继续导入。

3B. 有历史 Excel：备份、预检、修正、提交

Excel 仅用于 Leader 集中摄取历史或外部数据，不用于成员终端持续同步。

Gate B · Leader
1完整备份
2选择工作簿
3预检与修正
4提交与验证

准备

Gate A 通过；成员已创建；文件是小于 25 MB 的 .xlsx；工作表名和前四行结构不变，业务数据从第 5 行开始。

创建完整备份

在“导出 / 导入 → Excel 导入”点击“创建完整备份”，记录路径、时间和文件名。JSON 导出不含附件，不能替代完整备份。

运行只读预检

选择工作簿后点击“运行预检”。先看源行、实体、错误、警告；预检不写数据库。预检后不要改写或替换文件。

处理账号映射

来源姓名、缩写和大小写变体映射到实际账号。Owner 只能是 Leader/Sales；售前和售后 assignee 只能是 Tech；未知、停用、歧义或角色错误均阻断。

处理客户候选

核对主名称、别名、国家、域名和联系人。相似度只帮助缩小范围；不是同一法律实体时必须新建，不能为了清零错误随意排除。

应用修正并重新预检

修正后点击“应用修正并重新预检”。只有同一文件显示“可以导入”且阻断项为 0，才允许提交。

只提交一次

点击“导入并合并”，记录批次编号、新增、更新、归档、跳过和警告。结果无法确认时不要立即重试；重开程序核对批次和目标记录。

重复与增量验证

相同文件再次导入不应新增副本；保留原 dataset_id + external_key 只修改一个允许字段，应只更新原记录。空白表示不修改，显式清空使用 __CLEAR__。

必须人工补充：导入警告会在卡片和右侧“数据质量”标签显示数量角标。解决、忽略或重新打开后两处应同步；不能只看导入统计就认为数据完整。

6. JSON 定向分发与终端同步

每台电脑是独立本地数据库；当前版本不允许多人把同一个 SQLite 数据目录放在网络盘并发写入。

Gate D
Leader完整备份并选择目标 Sales
导出只包含该 Sales 负责的 Lead
Sales同一文件预检：错误 0、权限跳过 0
往返合并后回传 Leader，更新原 Lead

目标 Sales 应验证

  1. 确认导出目标用户名是本人。
  2. 选择文件并预检：源总数、允许数、权限跳过、错误、冲突。
  3. 只在错误和权限跳过均为 0 时导入。
  4. 核对客户、Lead、主联系人、活动、任务和本地新增内容。
  5. 重复导入，数量不应重复增长。

非目标 Sales 应验证

  1. 在另一终端选择同一包。
  2. 接收账号不匹配时必须拒绝。
  3. 不能通过改文件名绕过。
  4. 旧版无接收成员字段的包只能证明逐条权限过滤，不能证明新版定向分发。
  5. 附件本体不在 JSON 中，另行受控传递。
不要立即重试“结果无法确认”的导入。先重开 JPT，核对导航计数、目标记录和批次；只有确认没有记录本次导入后才重试。显示“部分完成”也不能当作完整成功。

该链路只同步技术任务和必需上下文，不使用 Sales JSON，也不让 Tech 导入 Excel。

Gate D · Leader + Tech
Leader完整备份，选定 Tech 导出全部未归档分配快照
Tech预检无阻断后导入，到业务卡片处理
回传Tech 保存更新，导出 .jptresult
Leader预检版本和归属，原子合并并回执
开始前：Leader 先创建完整备份，记录目标 Tech、售前/样品任务数、售后任务数和导出时间。旧版本升级使用增量数据库迁移，不应删除现有客户、Lead 或任务；升级后仍要抽查原卡片并第二次启动。

Leader 分发 .jpttask

建立真实分配

先在售前/样品或售后任务中选择启用中的 Tech 账号。测试可使用 qa.tech.01，但正式包不得发给共用账号或无法确认身份的成员。

进入正确页签

打开“导出 / 导入 → 技术任务包 / Tech Task Packages”；不要停留在“JSON 数据交换”或“Excel 导入”。

精确选择接收人

在“1 · 向技术人员分发任务”选中目标成员，点击“下载 .jpttask”。新包是当前终端上该 Tech 当时全部未归档分配的完整快照，不是增量包；新快照缺失的旧任务代表撤回分配。任一 Leader 后续签发的新快照都会替代此前其他 Leader 为同一 Tech 签发的旧快照。

受控传递

通过团队批准的内部渠道点对点发送，另通道告知文件名、任务数和时间。首版未做设备数字签名；内容校验和接收账号校验不能替代可信渠道。

Tech 预检、处理与导出 .jptresult

1 · 预检与导入

  1. 用被指定的 Tech 账号登录。
  2. 在“技术任务包”选择 .jpttask。
  3. 点击“预检分配包”，核对来源、接收人、任务数、错误、冲突和撤回警告。
  4. 仅当同一文件无阻断时点击“导入任务”；接受撤回警告后，缺失任务会归档。
  5. 到“售前 / 样品”与“售后”核对卡片和请求内容。

2 · 更新与回传

  1. 售前/样品更新本人允许的状态、进展、结果摘要、下一步、样品结果或报告链接。
  2. 售后更新状态、解决方案、满意度、经验教训和备注。
  3. 保存并重开卡片，确认更新仍在。
  4. 回到任务包页签，点击“下载 .jptresult”。
  5. 回传给原 Leader，等待“已合并”回执。

Leader 预检并合并 .jptresult

选择结果包

在“2 · 导入技术处理结果”选择 Tech 回传的 .jptresult，记录文件名与发送人。

预检结果包

核对来源 Tech、本 Leader 接收账号、源任务是否仍存在、是否归属原 Tech，以及任务基础快照。系统使用三方比较：Leader 与 Tech 同时修改同一结果字段且值不同时阻断；不同字段的变更可合并保留。更换文件会使预检失效，必须重新执行。

仅在无阻断时合并

错误和冲突均为 0 后点击“导入结果”。同一包中任一任务阻断时，整包不应部分静默写入。

验证与回执

在原 Leader 卡片核对状态和结果；售后任务同时核对 Lead 售后状态。重复导入同一包应为幂等无写入，最后向 Tech 确认已合并。

预检结果风险处理方式
接收人或组织不符包不属于当前账号/团队隔离包，不改名冒充；请 Leader 重新指定接收人
任务已改派、归档或缺失旧包的任务归属已失效不强制导入；由 Leader 核对有效结果后重新分发
完整快照撤回分配新快照不含旧任务；Tech 无未导出更改，或已导出且之后未再修改允许导入撤回警告，本地对应任务归档
本地未导出更改Tech 从未导出更改，或导出 .jptresult 后又修改撤回/刷新阻断；Tech 先重新导出，Leader 合并后再发新快照
同字段冲突Leader 与 Tech 已修改同一结果字段，且值不同阻断并人工对照；不同字段变更可安全合并，不静默覆盖
旧完整快照生成时间不新于已导入快照，或任务基线倒退拒绝导入；Leader 按当前任务重新导出
重复包同一包已成功导入应返回重复/无更改结果，不重复新增或改写
校验失败或包 ID 异常文件可能被篡改或同 ID 对应不同内容不继续；用可信渠道与发送人确认并重新导出
数据最小化：.jpttask 只包含完成任务所需的最小客户/需求上下文；.jptresult 只回传 Tech 允许的结果字段。两者均不含报价、金额、PO、输单原因、联系人、附件文件或完整备份。

8. 地图、坐标复核与出差规划

地图点位质量与业务地区是两套独立口径；近似坐标不能作为实际拜访终点。

治理与出访

精确

已确认经纬度，可用于地图定位；拜访前仍需核对地址和联系人。

近似

国家、城市或区域级参考，只用于发现分布，不能判断楼宇、路线终点或精确距离。

缺失

填写地址、城市、邮编和国家搜索候选，也可地图选点或人工经纬度；候选必须人工确认。

坐标复核

搜索 NordWerk Demo GmbH，输入不敏感的虚拟地址；核对候选完整地址、国家、坐标和服务商后保存。并发版本冲突时刷新，不静默覆盖。

地图复盘

按阶段、结果、业务地区和坐标质量筛选；离线底图失败时点位列表仍应可用，接口失败显示重试而不是 0。

出差计划

建立“QA Europe Visit”计划，按客户地理区域选候选，加入停靠点、预览路线、保存、导出；上传部分失败时只重试失败项，不重复成功项。

归档

确认计划可创建、查看、修改、归档。归档前出现确认；归档后活动计划不再显示，但不物理删除业务历史。
