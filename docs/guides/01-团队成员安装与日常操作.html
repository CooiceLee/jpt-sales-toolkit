A先独立完成安装验收

1. 选择并安装正确版本

设备应选择如何确认
Windows 10 / 11Windows x64 Setup .exe设置 → 系统 → 系统信息，确认 64 位
Mac M 系列芯片macOS Apple Silicon arm64 .dmg → 关于本机，芯片显示 Apple
Mac Intel 芯片macOS Intel x86_64 .dmg → 关于本机，处理器显示 Intel
内部未签名版本：只有在文件名、版本和 Leader 提供的校验记录一致时，才处理系统“未知发布者”提示。不提供 Linux 版本，也不要使用来源不明的命令关闭系统安全保护。

Windows 安装

  1. 完全退出旧 JPT，并关闭旧的本机浏览器页签。
  2. 运行 Windows x64 安装程序并按向导完成。
  3. 从“开始”菜单打开 JPT，不要继续用旧目录副本。
  4. 页面打开后确认标题栏为 v0.11.7-internal。

macOS 安装

  1. 通过 JPT 的退出入口完全退出旧程序；只关浏览器不等于退出。
  2. 打开与芯片匹配的 DMG，把 App 拖入“应用程序”。
  3. 在 Finder 推出 DMG。
  4. 从“应用程序”打开 JPT，确认标题栏版本。
升级后没有重新创建账号是正常的。账号、授权、附件和业务数据保存在独立数据目录。新版只替换程序；不要通过删除数据目录来“刷新界面”。若仍看到旧界面，应确认旧后台已退出、DMG 已推出，并从正确的应用副本重新打开。
新版会先备份再迁移。第一次打开旧数据时，程序会在本地 data/backups 生成并校验 pre_upgrade_...zip，校验通过后才更新数据库；失败会恢复原数据库并停止启动。离线恢复只接受这类自动 pre_upgrade ZIP，替换前还会保存当前数据库为 pre_recovery_current_*.sqlite；保存失败就不会开始恢复。不要删除这些文件，也不要在失败后继续录入数据。

升级后必须完成的数据核对

确认原账号

使用原用户名和本地密码登录；不应重新创建 Leader，也不应重新导入现有设备授权。

核对原记录

记录升级前后的客户和询盘总数，并打开一条原有卡片核对负责人、阶段和跟进内容。

核对附件

打开至少一个升级前附件，确认文件内容正常，而不是只查看附件数量。

第二次启动

完全退出后再次打开，确认账号、数量和附件仍一致。任一差异都应停止录入并保留截图和 data/logs/launcher.log。

2. 成员设备申请与激活

选择加入现有团队

已有团队成员选择“加入现有团队”，确认页面显示的是自己的姓名与预期角色。

下载设备申请

生成 .jptreq，点对点发给 Leader。不要把设备申请放入公开群或公共代码仓库。

接收两项内容

Leader 返回设备专属 .jptauth；16 位验证码应通过另一条可信渠道发送。两项都不要转发给其他成员。

导入并设置本地密码

导入授权、输入验证码、设置至少 8 位密码。姓名、角色或设备任一不符时停止，让 Leader 重新签发。

完成持久化检查

建立一条带唯一测试标识的记录，查看、修改、归档或删除；完全退出并重新启动，确认预期数据仍在。

Gate A 通过后再拿 Excel。程序安装、账号激活和本地保存必须在没有工作簿、没有 JSON 同步包的情况下单独通过。

3. 业务地区与跟进时间怎么筛

负责人业务地区

地区来自 Lead 负责人账号，不来自客户地址。五类固定值：

  • GLOBAL
  • 欧洲
  • 北美/加拿大/澳洲
  • 俄罗斯/土耳其/中东
  • 东南亚

全部地区才表示清除地区限制；GLOBAL 是真实业务归属。地区、负责人、技术人员、搜索和时间条件会同时生效。

两种时间口径

计划到期：已逾期、今日到期、未来 7 天都查看下一次计划跟进日期。没有计划日期的记录不会自动进入这些页签。

长期未跟进：先取最近正式跟进日期；没有则取询盘日期；再没有取创建日期。可用于找出长期没有实际活动的卡片。

筛选结果为空先检查什么正确动作
已逾期/今日/未来 7 天为 0卡片是否填写下一次计划日期查看页面的针对性空状态；需要时返回全部进行中补填计划
长期未跟进为 0时间门槛、负责人、地区、技术和搜索是否同时过窄逐项清除组合条件，而不是把 GLOBAL 当成全部地区
看到“从未正式跟进”是否确实没有正式跟进活动仍可查看询盘/创建日期；补记真实跟进，不要伪造日期

4. 卡片排序与 Sales 数据包

为什么不是按客户名称排列

每个工作页按最需要处理的业务日期排序：处理页优先较早询盘；跟进页优先最近计划日期；售前/样品优先进行中且临近到期；成交、履约和售后按各自阶段与关键日期排列。缺失或无效日期落在有效日期之后；刷新后同一组卡片顺序应保持稳定。

接收 Leader 定向 JSON

  1. 向 Leader 确认导出时选择的是本人账号。
  2. 在“JSON 数据交换”选择文件并运行预检，核对源总数、允许数、权限跳过数和错误数。
  3. 只有同一文件错误数为 0、权限跳过数为 0 时才可导入；若提示接收账号不匹配，停止并索取正确文件。
  4. 导入后核对结果是完整成功还是部分完成，再核对 Lead 数、客户、主联系人和原有本地活动。
  5. 再次导入同一文件，数量不应重复增长。
不要用 Excel 代替成员同步。Excel 由 Leader 做外部数据摄取；Leader → Sales 的日常分发使用定向 JSON。JSON 只携带附件元数据，附件本体与完整备份仍需独立传递。

5. 地图坐标质量

精确

已有经过确认的经纬度，可用于地图定位；拜访前仍应核对地址和联系人。

近似

仅按国家、城市或区域给出参考位置，不能用于判断楼宇、路线终点或实际距离。

缺失

没有可用坐标。应进入坐标复核补充地址、城市、邮编和国家，从候选结果中确认；也可地图选点或人工输入经纬度。

没有底图不等于数据丢失。地图底图和地址解析需要网络。地址搜索与批量地理编码会把位置字段发送给一个或多个外部服务；启用高德后，可回退故障会继续查询 Nominatim，界面显示实际候选服务商。高德只负责可选地理编码，不替换 CARTO/OpenStreetMap 底图；打开地图也会产生外部瓦片请求。普通成员不要自行配置或索取高德 Key，不允许外发的客户地址请使用人工经纬度或地图选点。离线或瓦片加载失败时，客户列表、筛选、坐标质量和人工修正仍应可用。

7. 常见异常

现象原因判断处理
提示旧版仍在运行只关闭了浏览器，后台进程仍占用数据目录回到旧版使用退出入口，确认完全停止后再打开新版
macOS 显示安装位置警告正在从 DMG 运行退出，拖入“应用程序”，推出 DMG，再从“应用程序”打开
升级后仍是旧界面打开了旧副本或旧页面关闭旧页签，核对应用位置和标题栏版本后重开
升级失败并停止启动备份校验、schema 迁移或迁移后数据库检查未通过不要删除数据目录；保留提示和 launcher.log，使用自动生成的 pre_upgrade 备份联系 Leader/管理员恢复
授权设备不匹配使用了其他电脑或其他成员的授权本机重新生成申请，由 Leader 对应成员重新签发
地图没有底图离线或底图服务不可用继续使用列表；需要定位时联网后重试，不要把近似点当精确点
地址搜索失败页面会区分无结果、断网、超时、限流或服务配置错误按具体提示重试或人工选点；不要把服务故障当作客户地址错误
