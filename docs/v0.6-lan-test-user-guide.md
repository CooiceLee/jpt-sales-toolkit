# JPT Sales Toolkit v0.6 局域网测试使用说明

## 测试目的

本次测试用于确认销售漏斗管理工具在真实团队使用场景下是否符合工作习惯，重点验证：

- 询盘录入、客户识别、Lead 分配是否顺畅。
- 销售跟进、成交信息、售前/售后记录是否能完整沉淀。
- Leader、Owner、Collaborator、Watcher 的权限是否符合实际管理需要。
- Dashboard、地图、阶段卡片和统计数字是否准确。
- 多人同时使用时是否存在刷新、保存、权限或数据错乱问题。

## 访问方式

请在公司局域网内访问：

```text
http://<测试服务器IP>:8000
```

建议浏览器：

- Chrome
- Edge
- Safari

如果无法打开页面，请先确认：

- 电脑已连接同一个局域网。
- 访问地址中的 IP 和端口填写正确。
- 浏览器没有拦截本地网络访问。

## 建议测试流程

### 1. 登录与首页

1. 打开测试地址。
2. 输入账号和密码登录。
3. 检查左下角显示的用户名和角色是否正确。
4. 查看 Dashboard 的统计数字和地图是否正常加载。

需要反馈的问题：

- 登录失败。
- 页面打不开或加载很慢。
- 角色显示不正确。
- Dashboard 数字明显不合理。

### 2. 录入新询盘

1. 进入 `Parser` 或询盘录入页面。
2. 粘贴一封客户询盘邮件。
3. 检查系统解析出的公司、联系人、邮箱、国家、需求内容是否合理。
4. 确认客户归属后创建 Lead。
5. Leader 测试分配 Owner、Watcher 或 Collaborator。

需要反馈的问题：

- 邮件解析明显错误。
- 同一客户重复创建。
- 无法正确选择负责人。
- 创建后列表中找不到该 Lead。

### 3. 销售跟进

1. 打开自己负责的 Lead。
2. 进入 `Follow-ups`。
3. 新增一条跟进记录。
4. 尝试编辑刚新增的跟进记录。
5. 检查中间卡片和左侧数字是否刷新。

需要反馈的问题：

- 保存后记录没出现。
- 编辑后内容不更新。
- Follow-up 数量不一致。
- 新增跟进后阶段没有正确变化。

### 4. 成交与履约

1. 进入 Lead 详情的 `Deal`。
2. 填写报价号、PO 号、合同金额等信息。
3. 保存后检查该 Lead 是否进入正确阶段。
4. 进入 `Fulfillment`，修改履约状态。
5. 检查卡片状态和左侧计数是否同步。

需要反馈的问题：

- Deal 信息保存失败。
- 已成交 Lead 仍出现在错误页面。
- Fulfillment 状态修改后卡片不刷新。
- 金额统计与实际输入不一致。

### 5. 售前/售后

1. 对一个 Lead 新增售前或售后任务。
2. 修改任务状态、问题描述或解决方案。
3. 检查 After-sales 列表是否显示对应卡片。
4. 检查状态变化后统计是否同步。

需要反馈的问题：

- 任务保存失败。
- 已有售后任务但列表不显示。
- 状态更新后卡片不刷新。
- 技术角色看到不该看到的数据。

### 6. 附件

1. 进入 Lead 详情的 `Files`。
2. 上传一个测试文件。
3. 修改文件分类、版本号或显示名称。
4. 下载文件确认内容正确。
5. 测试结束后可归档测试附件。

需要反馈的问题：

- 上传失败。
- 分类修改后无法下载。
- 文件名或版本号显示错误。
- 不该访问附件的角色可以访问。

### 7. 地图与坐标

1. 打开 Dashboard 或 Review Map。
2. 查看客户点位是否符合实际地区。
3. 对需要修正的客户使用 `Fix Location`。
4. 保存后刷新，确认点位变为已锁定状态。

需要反馈的问题：

- 地图不显示。
- 点位明显错误。
- 手工定位保存失败。
- 下拉筛选或弹窗被地图遮挡。

## 测试注意事项

- 本次是试运行环境，可以使用测试数据，但不要录入敏感客户隐私信息。
- 请不要修改其他人负责的 Lead，除非测试权限场景。
- 测试附件请使用无敏感内容的小文件。
- 如果发现数据明显异常，请先停止继续操作并反馈。
- 每天测试结束前，管理员会做一次备份。

## 当前已知边界

- 本次测试优先验证业务流程和多人协作，不验证正式公网访问。
- 局域网服务需要测试服务器保持开机。
- 如服务器重启，短时间内可能无法访问，稍后重试。
- 试运行期间 UI 和字段可能会根据反馈继续调整。
