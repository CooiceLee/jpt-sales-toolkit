## 已修补问题

| 级别 | 原风险 | 本版处理 |
|---|---|---|
| P1 | 仪表盘请求失败时仍可能显示 0，容易被误判为真实空数据 | 失败时清空为 `—`，显示可见错误与重试；地图失败不再覆盖 KPI 状态 |
| P1 | 窄屏同时隐藏主侧栏与图标栏 | 保留可横向/纵向滚动的移动端 rail，KPI 3/4/5 列自适应 |
| P1 | 登录 401、授权状态检查失败可能被解释为会话过期或进入旧登录旁路 | 匿名登录保留后端真实错误；授权状态不可确认时阻断进入业务页 |
| P1 | JSON 有权限跳过或错误时仍可能被当作完整成功 | 同一文件只有 `errors=0` 且权限跳过为 0 才能提交；结果明确区分成功、部分完成和失败 |
| P1 | Leader→Sales→Leader 往返可能新建来源副本或遗漏显式清空 | 使用来源 Lead ID 命中原记录；业务字段采用明确白名单，支持 `null`/空值清除且不覆盖 owner、客户关联和审计元数据 |
| P1 | Owner 更新、assignment、审计或活动可能跨事务产生不一致 | Owner CAS 先行，Lead/assignment/audit/activity 进入统一事务并在异常时回滚 |
| P1 | Collaborator 写权限依赖排除列表 | 改为允许列表，未知字段默认拒绝 |
| P1 | 附件文件与数据库写入失败可能留下半成品 | 拒绝空文件名，精确去重；数据库失败时补偿删除或回移文件 |
| P1 | Excel 归档/恢复不递增版本，普通更新可触碰归档实体 | 生命周期操作递增 `row_version`；普通 Customer/Lead 更新拒绝归档记录 |
| P1 | Excel 已通过预检但未建立完整备份仍可提交 | 提交同时要求当前文件预检可用且本次会话完整备份成功 |
| P2 | 重复登录/切换账号可能重复绑定事件，或丢失右侧未保存内容 | 初始化幂等；搜索、切换账号、退出和注销前统一触发未保存确认 |
| P2 | 出差计划只能创建，缺少可纠正的归档入口 | 增加计划归档按钮、确认、刷新和中英提示 |
| P2 | 多文件上传部分成功后重试容易重复上传 | 显示成功数量，清空选择器，并明确只重选剩余文件 |
| P2 | LAN 演示账号使用可预测口令或刷新真实成员口令 | 六个保留演示账号每次生成随机一次性口令；清单权限为 `0600`，其他成员不写入清单 |
| P2 | 源码启动时自动安装依赖，失败语义和环境可控性差 | `run.py` 只检查依赖并给出明确安装命令，不在启动期间修改环境 |
| P2 | 旧一次性 Excel 迁移脚本含本机路径且可直接写数据库 | 移除硬编码路径；要求调用者提供源/目标，并显式确认已有验证备份；正式流程仍只使用 App 导入 UI |
| P2 | 前端数据交换模块超过单模块边界 | 将呈现/备份职责拆到 `data-transfer-view.js`，全部前端模块保持不超过 160 行 |
| P2 | 历史文档和源码可能把本机路径、业务工作簿名带入公开仓库 | 已脱敏并增加 `test_release_hygiene.py`；业务数据库、同步包、授权、密钥和生成目录禁止跟踪 |
