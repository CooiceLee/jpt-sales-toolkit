## 这一版相对 0.13.3 多了什么

本轮独立审计（r21–r30）与自主开发修好的产品缺陷，每一项都有回归与变异验证：

| # | 缺陷 | 现在的行为 |
|---|---|---|
| 1 | 路线与日程下半部信息割裂：停靠点与交通段各自成列表，要反复滚动才能看懂一天 | 一条时间线读全程，停靠与交通按日期同列排布，附总览与日期导航 |
| 2 | 不同日期、不同距离的交通段被合并成一行；搜索结果按合并前的列表定位，挂错卡片 | 只有全部事实一致才合并；搜索与地图按同一份行标识定位 |
| 3 | 地图盖住公共操作栏；地图延迟定位仍作用于已切换的计划 | 分层与栏高统一测量；切换计划后定位关闭 |
| 4 | 交通高亮与编辑对象不一致；拖动排序后回弹 | 选中身份统一为 leg_key + 成员集合；排序落位与草稿一致 |
| 5 | 约定拜访时间入口不易找、搜索每次输入都重建输入框 | 「设置约定时间」入口与「设置客户约定拜访时间」面板；搜索连续输入与中文输入法不再打断 |
| 6 | 填了 2 天日期仍显示 1 天；提示已保存但试算仍被拦 | 卡片明说「上次计算结果，待更新」；所有路线入口用同一判断 |
| 7 | 切换拜访会丢掉未保存的拜访目的 | 按「计划 + 停靠点」保存草稿，离开有保护，公共栏点名是谁的哪一项 |
| 8 | 重绘会更新草稿基准，保存可能带着最新版本号无提示覆盖别人的修改 | 编辑基准只在保存成功或明确放弃后才移动；目的被改过时并列两个版本由读者选择 |
| 9 | 「不脏」被当成「可以照原样写回」：一次保存会顺带把输入框里的旧目的写回库 | 没有待保存修改时请求**不含** `visit_purpose`；改回旧基准但服务端已变，仍算待保存并走冲突确认 |

## 不包含什么

- 不改数据模型（仍是 schema 15）、不改权限规则、不改调度算法、风险规则与金额口径。
- 不含 macOS Intel 与 Linux 构建。
- 未确认的手填约定日期与计算结果仍共用 `planned_date`（记录在案的业务限制，本轮未改）。
- 真实设备的原生安装与覆盖升级**没有做**，见下表 Pending。

## 升级与分发

- 从 0.13.1 / 0.13.2 / 0.13.3 覆盖升级不触发数据库迁移（同为 schema 15）；从更早版本升级会在写入前自动生成并验证 `pre_upgrade` 备份。
- 升级前请先按《团队升级操作与回退说明》做一次备份；**旧版程序读不了升级后的库，回退必须程序与备份一起退**。
- 未做原生安装验证之前，不得把本版描述为"团队升级已验证"或"可以安全分发"。
