状态：地图模块治理及本机 macOS Intel 候选已完成并通过本地验收；macOS Apple Silicon arm64 候选已完成架构与磁盘映像静态校验；Windows x64 候选已在隔离兼容环境完成构建、安装、升级、恢复和卸载数据保留验证。当前产物均为 `UNSIGNED-INTERNAL` 本地团队测试候选，不等同于已发布稳定版。Windows 10/11 原生运行、Apple Silicon 原生运行、真实高德 Key 和团队终端验收仍是发布 Gate，本轮未推送 Git。

## 地图治理结论

- 地理编码已从旧单服务实现拆为 provider-neutral 服务：默认使用 Nominatim；管理员显式配置高德 Web Service Key 后优先使用高德。高德空结果、网络、超时、配额或无效响应可回退 Nominatim，鉴权/权限错误保持可见且不被回退掩盖。界面显示本次候选实际来自 `amap` 或 `nominatim`。
- 高德返回坐标在服务端从 GCJ-02 转为 WGS84，数据库、Leaflet、复盘地图、坐标复核和出差规划统一保存/读取 WGS84。
- 经度、纬度的有限值和范围校验已覆盖客户创建、修改、批量修复、询盘摄取和 Excel 导入；旧库中的空值、非完整或越界坐标不会作为精确点显示，而会进入近似/缺失复核口径。
- 自动搜索和批量首选候选只保存为待复核的中等置信度坐标；只有人工选点或确认保存才标记为人工核验并锁定，不能把自动结果误当作精确地址。
- Leader、Lead owner 和 collaborator 可修正有权访问客户的坐标；watcher 与 Tech 为只读，修正和批量入口不会显示，后端写接口仍会再次拒绝越权请求。
- 地址搜索与坐标保存互斥；请求 epoch、编辑快照和 `row_version` 乐观锁阻止旧搜索结果、切换客户或双端编辑覆盖新数据。手动移动坐标或修改地址会清除旧标准化地址，空字段也可明确保存。
- 单条搜索和批量地理编码均在界面明确提示：地址字段会发送给一个或多个外部地理编码服务。若高德触发可回退故障，同一查询可能随后发送给 Nominatim。底图仍由 CARTO/OpenStreetMap 瓦片提供，高德当前只承担可选地理编码，并未替换底图。
- Review Map、Coordinate Review、批量地理编码和 intake geocoding 已拆分为小模块；地图失败会清除旧点位和旧批处理状态，不再把上一次结果伪装为当前结果。
