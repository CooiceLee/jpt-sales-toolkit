# JPT Sales Toolkit v0.8.7-internal 试运行操作手册

## 1. 文档目的

这份手册用于内部试运行。目标是让 Leader、销售和技术人员可以按固定路径完成日常操作，也让管理员知道备份、恢复、迁移和回归验证的边界。

当前版本定位：
- 版本：`v0.8.7-internal`
- 形态：本地单机版，FastAPI + SQLite + Web UI
- 入口：`http://127.0.0.1:8000`
- 数据库：`data/database.sqlite`
- 附件目录：`data/attachments/`
- 备份目录：`data/backups/`

当前已验证能力：
- 真实旧数据迁移可执行、可验证。
- 主链路浏览器 full 回归通过。
- 客户、联系人、lead、follow-up、after-sales、附件、导出/导入、坐标治理可试运行。
- Data Review 可做只读经营复盘，Leader 看全局，Sales 看自己负责或协作的数据。
- Trip Planner 可创建计划、添加客户、生成离线启发式路线、回填拜访结果并导出 Markdown / CSV。
- Coordinate Review 支持 Needs Review / Missing / Verified 队列、搜索、地图选点、经纬度录入和地址解析选点。
- 备份、恢复、备份保留策略已完成演练。

当前边界：
- 不支持多人实时在线同步。
- JSON 导出只包含附件元数据，不包含附件文件本体。
- 恢复是整库替换，不做增量恢复。
- 前端暂无完整独立 Admin 页面，备份/恢复/迁移在试运行阶段主要通过命令或 API 完成。

### 3.3 权限边界

| 角色 | 可见范围 | 可编辑范围 |
|---|---|---|
| Leader | 全部 leads 和客户 | 全部字段、owner/watcher/collaborator 分配、备份恢复 |
| Owner | 自己负责的 leads | lead 基本业务字段、客户和联系人、follow-up、任务 |
| Collaborator | 被分配协作的 leads | 允许的业务字段、follow-up/comment，不可改 owner 和成交关键字段 |
| Watcher | 被分配知悉的 leads | 只读，可补充 comment/风险提示类信息 |
| Tech | 自己任务相关 leads | 自己负责的售前/售后任务 |

试运行时如果出现“看不到 lead”或“保存被拒绝”，先确认该用户是否是 owner、collaborator 或 watcher。

## 4. 日常业务操作

### 4.1 接收询盘并创建 Lead

入口：`Parser`

操作步骤：
1. 将客户邮件原文粘贴到左侧输入框。
2. 点击解析按钮，检查系统提取出的客户、联系人、需求字段。
3. 系统会按邮箱、域名、公司名匹配已有 Customer。
4. 确认是新客户还是已有客户。
5. 选择 owner。
6. 提交后系统一次性创建 Customer + Lead + Owner Assignment。

注意：
- 同一客户的新需求应创建为该客户下的新 Lead。
- 如果匹配结果不确定，优先人工确认 Customer 归属。
- 原始邮件会保留在 lead 中，方便复盘。

### 4.2 查看和筛选 Leads

入口：`Handler`

常用操作：
- 按阶段筛选：`New / Assigned / Following / Quoted / Won / Lost`
- 搜索客户名、联系人、标题等文本。
- 点击 lead 卡片打开右侧详情面板。

各模块含义：
- `Handler`：新询盘和待分配/待处理线索。
- `Follow-up`：跟进中线索。
- `Sampling`：打样/售前相关线索。
- `Deal`：报价、成交、丢单相关线索。
- `Fulfillment`：Won 后履约状态跟踪。
- `After-sales`：售后服务状态跟踪。

### 4.3 编辑 Lead、Customer 和联系人

入口：Lead 详情面板

操作步骤：
1. 打开 lead 详情。
2. 在 `Basic`、`Customer`、`Requirement` 等 tab 中修改字段。
3. 联系人字段支持编辑：姓名、职位、邮箱、电话。
4. 点击 `Save Changes`。

校验规则：
- 联系人姓名和邮箱至少填写一项。
- 邮箱格式必须正确。
- 同一客户下联系人邮箱不能重复。
- 如果保存时提示版本冲突，刷新详情后重新编辑。

### 4.4 分配 Owner、Watcher、Collaborator

入口：Lead 详情面板 `Basic` tab 底部 `Team & Assignments`

Leader 可执行：
- 修改 Owner。
- 添加或移除 Watcher。
- 添加或移除 Collaborator。

注意：
- 修改 Owner 后，新 owner 应能看到历史记录。
- Watcher 是只读角色，不应修改核心业务字段。
- Collaborator 可以协作跟进，但不能改 owner、成交金额、PO、Won/Lost 等关键字段。

### 4.5 Follow-up

入口：Lead 详情面板 `Follow-ups` tab

操作：
1. 点击新增 follow-up。
2. 记录沟通方式、内容、下一步动作。
3. 保存后时间线会显示更新人和时间戳。
4. 测试记录或误操作记录可归档。

要求：
- 正式客户沟通应记录为 follow-up，而不是只写在备注里。
- 更新内容应能支持后续复盘，例如客户需求变化、竞争对手、价格反馈、拜访计划。

### 4.6 After-sales

入口：Lead 详情面板 `After-sales` tab

操作：
1. 新增售后任务。
2. 选择问题类型和状态。
3. 填写 solution。
4. 保存后可在售后列表和 lead 详情中查看。
5. 测试任务或误操作任务可归档。

注意：
- 售后任务归属于同一条 lead，保证售前、成交、售后可以全流程对应。
- 技术人员只能处理自己相关任务。

### 4.7 附件

入口：Lead 详情面板 `Files` tab

支持：
- 上传附件。
- 下载附件。
- 归档附件。

限制：
- 单文件建议不超过 25MB。
- 支持常用文档和图片类型。
- 数据库只保存附件元数据，文件本体保存在 `data/attachments/`。

注意：
- JSON 导出不包含附件文件本体，只包含附件元数据。
- 做整库备份时会包含 `attachments/` 文件。

## 5. 坐标治理与地图复盘

### 5.1 Review Map

入口：`Dashboard` 顶部地图区域

筛选：
- Stage：按销售阶段筛选。
- Outcome：Open / Won / Lost。
- Region：按区域筛选。
- Coordinate：All / Exact only / Needs geocode。

点位含义：
- `Exact`：已有客户坐标，可用于路线规划基础。
- `Auto Approximate`：自动地理编码坐标，需人工确认。
- `Country Fallback`：国家级临时点位，只能用于分布观察，不能用于拜访地址。
- `Missing`：缺少可显示坐标，需要补充地址或手动坐标。

### 5.2 手动修正坐标

入口 1：Review Map 点位弹窗

操作：
1. 点击客户点位。
2. 点击 `Fix Location`。
3. 在地图上点击正确位置，或手动输入经纬度。
4. 点击 `Save Location`。
5. 刷新后确认点位为 exact，并显示 locked。

入口 2：`Coordinate Review`

操作：
1. 打开 `Coordinate Review`。
2. 查看 `Needs Review` 和 `Missing Coordinates`。
3. 优先处理 lead 数量多的客户。
4. 点击 `Add` 或 `Fix`，完成坐标保存。

保存效果：
- `geocode_source = manual`
- `geocode_confidence = high`
- `geocode_locked = true`

人工锁定后，自动地理编码不应覆盖该坐标。

### 5.3 批量 Geocode

入口：Review Map 的 `Batch Geocode`

适用：
- 客户有国家、城市、地址，但缺少坐标。
- 需要先批量补一版自动坐标，再人工审核。

注意：
- 批量 geocode 使用外部地理编码服务，结果只作为候选坐标。
- 批量 geocode 后仍应在 `Coordinate Review` 中人工确认重点客户。

## 6. 数据导出与导入

入口：`Export / Import`

### 6.1 导出

操作：
1. 打开 `Export / Import`。
2. 点击 `Export My Data`。
3. 浏览器下载 JSON 文件。

导出内容：
- 当前用户可见的 customers。
- 当前用户可见的 leads。
- contacts、activities、after-sales tasks。
- attachments 元数据。

不包含：
- 附件文件本体。

### 6.2 导入

操作：
1. 打开 `Export / Import`。
2. 选择 JSON 文件。
3. 点击 `Import & Merge`。
4. 阅读导入报告：新增、更新、跳过、错误。

规则：
- Leader 可导入全部相关数据。
- 非 leader 只能导入自己负责或有权限的 leads。
- 系统按 `legacy_inquiry_id`、源 lead UUID、客户邮箱和公司名做匹配合并。
- 重复导入应保持幂等，不应产生重复 lead。

导入前建议：
- 先做一次备份。
- 导入后检查 Dashboard、Handler、客户详情和地图。

## 7. 备份、恢复和保留策略

### 7.1 创建备份

推荐在以下时点创建备份：
- 每天试运行开始前。
- 批量导入前。
- 批量坐标修正前。
- 迁移或恢复前。
- 试运行结束后。

命令方式：

```bash
cd /Users/liliang/Desktop/jpt-sales-toolkit
python3 - <<'PY'
from pathlib import Path
from backend.services.admin_service import AdminService

data_dir = Path("data")
report = AdminService(data_dir=data_dir).backup(data_dir / "backups", "manual")
print(report["backup_path"])
print(report["backup_size"])
print(report["cleanup"])
PY
```

API 方式：

```bash
curl -s http://127.0.0.1:8000/api/admin/backup \
  -H "Authorization: Bearer <TOKEN>" \
  -X POST
```

备份包内容：
- `database.sqlite`
- `attachments/`
- `manifest.json`

备份使用 SQLite online backup 快照，避免直接压缩 live 数据库造成不一致。

### 7.2 备份保留策略

自动策略：
- 每次创建备份后自动清理旧备份。
- 保留“最近 10 个备份”或“最近 30 天备份”中更宽松的集合。
- 同一秒连续备份会自动追加后缀，避免覆盖。

手动清理 API：

```bash
curl -s http://127.0.0.1:8000/api/admin/backups/cleanup \
  -H "Authorization: Bearer <TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{"keep_count":10,"keep_days":30}'
```

### 7.3 恢复备份

恢复会整库替换：
- 替换 `database.sqlite`
- 替换 `attachments/`
- 恢复前会尽量创建 `pre_restore` 备份
- 如果当前数据库已经损坏，`pre_restore` 失败不会阻止从有效备份恢复

命令方式恢复时，建议先停止服务：

```bash
cd /Users/liliang/Desktop/jpt-sales-toolkit
lsof -iTCP:8000 -sTCP:LISTEN -n -P
kill <PID>
```

执行恢复：

```bash
python3 - <<'PY'
from pathlib import Path
from backend.services.admin_service import AdminService

backup_path = Path("data/backups/<backup-file>.zip")
report = AdminService(data_dir=Path("data")).restore(backup_path, "manual-restore")
print(report)
PY
```

恢复后重启服务：

```bash
python3 run.py --port 8000
```

恢复后检查：

```bash
sqlite3 data/database.sqlite "PRAGMA integrity_check;"
sqlite3 data/database.sqlite "SELECT COUNT(*) FROM leads WHERE archived_at IS NULL;"
```

```bash
SELECT COUNT(*)
FROM leads l
WHERE l.archived_at IS NULL
  AND NOT EXISTS (
    SELECT 1
    FROM lead_assignments la
    WHERE la.lead_id = l.id
      AND la.assignment_type = 'owner'
      AND la.user_id = l.owner_id
      AND la.archived_at IS NULL
  );
"
```

```bash
WHERE archived_at IS NULL
  AND (summary LIKE '%[regression]%' OR payload_json LIKE '%[regression]%')
UNION ALL
SELECT 'tasks', COUNT(*)
FROM after_sales_tasks
WHERE archived_at IS NULL
  AND (solution LIKE '%[regression]%' OR issue_type LIKE '%[regression]%')
UNION ALL
SELECT 'attachments', COUNT(*)

WHERE archived_at IS NULL
  AND original_name LIKE '%regression%';
```

三个计数应为 `0`。

## 11. 常见问题

### 看不到某条 lead

检查：
- 当前用户是否为 Leader。
- 当前用户是否是 owner、collaborator 或 watcher。
- lead 是否被归档。
- 阶段筛选是否过滤掉了该 lead。

### 保存时报 409 冲突

原因：记录已被其他操作更新，`row_version` 变化。

处理：
1. 关闭详情或刷新详情。
2. 重新编辑。
3. 再保存。

### 地图点位不准确

处理：
1. 打开 `Coordinate Review`。
2. 找到该客户。
3. 点击 `Fix`。
4. 手工选择精确位置并保存。
5. 确认显示 locked。

### 导入后数据不符合预期

处理：
1. 查看导入报告中的 skipped 和 errors。
2. 确认导入账号权限。
3. 检查是否导入了不包含附件本体的 JSON。
4. 如影响范围较大，从导入前备份恢复。

### 附件列表有元数据但无法下载

可能原因：
- JSON 导入只导入了附件元数据。
- 对应文件不在 `data/attachments/`。

处理：
- 使用完整备份恢复附件文件。
- 或重新上传该附件。
