# JPT Sales Toolkit 0.11.6-internal 本地测试候选验证结果

验证日期：2026-07-28

状态：JSON 定向分发、联系人关联、记录原子性和六类工作卡片固定排序已经完成源码与隔离数据验证；完整源码回归通过。macOS Apple Silicon 与 Intel 安装镜像已完成静态和磁盘映像检查，但本轮没有取得两个 macOS 架构的原生运行 Gate；Windows 正式 Inno Setup 构建仍以原生 Windows / GitHub Runner 为发布门。本版本是 `UNSIGNED-INTERNAL` 团队测试候选，不是已通过三平台验收的稳定发布版，本轮未推送 GitHub。

## 真实 JSON 问题根因与修复

用户提供的旧版全量 JSON 在仓库外只读使用，所有导入验证均写入临时数据库，没有触碰当前安装数据。

- 文件包含 488 条 Lead、169 个客户、223 个联系人和 421 条活动；三个负责人组分别为 251、133、104 条。
- 目标 Sales 按权限应取得 133 条。旧逻辑只成功 17 条，跳过 471 条并报告 204 个错误；该结果与团队截图完全一致。
- 第一根因是旧联系人校验直接对空邮箱执行 `.strip()`，导致目标范围内 88 个客户合并失败。
- 第二根因是导出端 `primary_contact_id` 属于来源数据库 ID，导入时没有映射为目标数据库联系人 ID；116 条带主联系人的 Lead 因此失败，只有 17 条不带主联系人的 Lead 成功。
- 修复后目标账号第一次导入得到 95 个客户、107 个联系人和 133 条 Lead；其中 116 条主联系人引用全部有效，错误和警告均为 0。其余 355 条属于另外两名负责人，按权限正确跳过。
- 第二次导入不新增客户或 Lead，只更新同一批 133 条记录；目标 Sales 可见数量保持 133，证明幂等和权限结果一致。

本版同时增加以下保护：

- Leader 导出给 Sales 时必须先选择接收成员，导出数据只包含该成员作为负责人的 Lead；文件记录接收账号，其他成员导入会被拒绝。
- 旧版没有接收账号字段的 JSON 保持兼容，但仍逐条执行当前账号权限过滤。
- 联系人来源 ID 统一映射为本地 ID；只有姓名、没有邮箱的多个联系人可独立存在，不会因空字符串被错误合并。
- 客户、联系人和 Lead 使用记录级 SQLite savepoint。单条记录失败会回滚该记录及从属写入，其他合法记录仍可继续，不再留下半写入客户或联系人。

## 工作卡片排序口径

工作卡片此前主要依赖数据库返回顺序和局部筛选后的数组顺序，因此用户看到的顺序既不稳定，也没有统一业务含义。本版将排序收敛为独立前端模块，并为后端列表增加稳定兜底顺序：

- 处理：询盘日期由早到晚，缺失时回退创建日期。
- 跟进：下一次计划跟进日期由近到远；缺失计划日期排后，同日优先较久未产生正式活动的记录。长期未跟进筛选使用最近业务活动时间优先。
- 售前 / 样品：进行中优先，到期日由近到远；无到期日排后，同值按任务更新时间由新到旧。
- 成交：已报价优先并按报价日期由早到晚；已丢单按最近业务日期由新到旧。
- 履约：未完成优先并按 PO 日期由早到晚；已完成记录按 PO 日期由新到旧。
- 售后：Open / In Progress 优先并按最近到期日；已解决记录按任务更新时间由新到旧。
- 无效、含糊或不完整日期不参与错误的字典序比较，统一排在有效日期之后；所有同值最终按询盘编号和内部 ID 稳定排序。

## Windows 构建状态

Windows 正式交付目标仍是原生 Windows x64 Inno Setup EXE。本轮在 macOS 隔离环境重新校验了 Wine、Windows Python、Inno Setup 和 win_amd64 wheelhouse，但 macOS 在 `dyld_start` 前阻止未签名的临时 Wine 工具链。两种有界、仅限临时副本的处理均未成功，已停止继续绕行，没有生成或冒充新的 Setup EXE。

本轮已经生成独立标记的 Windows x64 portable test fallback：

- 产物：`release/JPT-Sales-Toolkit-0.11.6-internal-Windows-x64-PORTABLE-UNSIGNED-INTERNAL.zip`
- 大小：19,466,872 bytes
- SHA-256：`313ade8727ae45715f182c502f2b3931d3d0a9286e557054b1cf5c6680a2e419`
- 内置官方 CPython 3.12.10 amd64；24 个运行依赖无缺失或版本冲突，37 个 EXE / DLL / PYD 均为 AMD64。
- ZIP 解包后逐文件哈希与打包前一致，应用源码与当前生产源码快照对比为 `changed=0 / missing=0 / extra=0`。
- 未包含用户数据库、账号、团队配置、授权包、Excel、JSON 业务数据或实际私钥材料。
- 安装脚本只写入当前用户的 `%LOCALAPPDATA%\Programs\JPT Sales Toolkit`，用户数据继续位于独立的 `%LOCALAPPDATA%\JPT Sales Toolkit\data`；不要求管理员权限，不使用 PowerShell 执行策略绕过、镜像删除或清理命令。
- 首轮团队实机发现带空格路径下，`%~dp0` 末尾反斜杠会让 Robocopy 合并相邻引号参数。修订包先将来源目录规范化为无尾反斜杠的绝对路径，再分别传入来源和目标；静态回归固定该约束，旧哈希已作废。

该 ZIP 只用于 Windows 10/11 原生 Gate A，不等于 Setup EXE 或平台验收通过。正式 Setup 仍须由 GitHub `windows-2022` 或受控原生 Windows 构建机生成并完成安装、0.11.5 覆盖升级、恢复、二次启动和卸载保数验证。

## 数据保护结论

- 安装程序与 portable 程序文件不得包含业务数据库、附件、账号、`.jptauth`、`.jptreq`、业务 XLSX、JSON 数据包或地图 Key。
- Windows 和 macOS 用户数据仍位于应用目录之外；覆盖程序文件不会主动删除数据目录。
- 数据库迁移前的 `pre_upgrade` 完整备份和失败自动恢复门没有被本版绕过。无论平台，成员升级前仍需完整退出旧 JPT、记录客户/Lead 数量并确认一个原附件。
- 本轮构建、回归和真实 JSON 验证均使用仓库外只读输入或临时数据目录，没有写入当前安装数据库。
