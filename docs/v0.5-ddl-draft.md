# JPT Sales Toolkit v0.5 DDL Draft

This document defines the MVP database schema for the local-first rebuild.
Target storage engine: SQLite 3.42+.

## 1. Schema Rules

- Primary keys use text UUID/ULID values.
- Human-readable IDs use `display_id`, generated separately.
- No hard delete in MVP. Archive is implemented with `archived_at`.
- `updated_at`, `updated_by`, and `row_version` are required on mutable business tables.
- JSON payloads are stored as text columns containing JSON strings.

## 2. Display ID Strategy

- Format: `JPT-{YYMM}-{NNNN}`
- Example: `JPT-2604-0001`
- Sequence resets monthly.
- Uniqueness is guaranteed by a `display_sequences` table inside a transaction.

```sql
CREATE TABLE IF NOT EXISTS display_sequences (
    period_ym TEXT PRIMARY KEY,          -- e.g. 2604
    next_value INTEGER NOT NULL
);
```

Generation rule:

1. Start an `IMMEDIATE` transaction.
2. Read or create the current `period_ym` row.
3. Increment `next_value`.
4. Format the number as `JPT-{period_ym}-{NNNN}`.
5. Commit.

## 5.1 Ownership Sync Rule

`leads.owner_id` is a denormalized convenience field used for fast filtering and list queries.

Service-layer invariants:

1. each lead must have exactly one active `lead_assignments` row with `assignment_type = 'owner'`
2. `leads.owner_id` must always match that assignment row
3. owner changes must update both places inside one transaction
4. any mismatch is a data integrity bug and should be rejected by write services

## 7. Archive Behavior

Archive endpoints set `archived_at = CURRENT_TIMESTAMP` and bump `row_version`.
Archived records are hidden from default list APIs unless `include_archived=true`.

## 8. Auth Strategy

MVP auth uses JWT bearer tokens.

- Token storage: browser local storage
- Expiry: 7 days
- Request header: `Authorization: Bearer <token>`
- Logout removes local token

This is acceptable for the local-first MVP. If the product moves to multi-user online deployment, consider switching to httpOnly cookies.

## 9. Service-Layer Validation Notes

- `customer_contacts.UNIQUE(customer_id, email)` is acceptable even though SQLite allows multiple `NULL` values.
- MVP service rules should enforce:
  - duplicate non-null contact emails under one customer are rejected before insert
  - a primary contact should normally carry an email when the source record contains one
