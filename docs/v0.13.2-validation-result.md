# JPT Sales Toolkit v0.13.2-internal 验证证据账本

日期：2026-09-07

性质：**安全热修**。只包含一处修复及其回归，不含任何界面改造或业务变更。状态 `UNSIGNED-INTERNAL`。

## 为什么有这一版

`v0.13.1-internal` 的页面路由把请求路径直接拼在页面目录后面，只判断文件是否存在就发送。URL 是文本，`%2e%2e/VERSION` 就是一段指向页面目录之外的文本：

```text
GET /%2e%2e/VERSION            → 200，返回 0.13.1-internal
GET /..%2fVERSION              → 200
GET /%2e%2e/backend/app_v2.py  → 200，返回后端源码
```

不需要登录。凡是能连到这个 HTTP 服务的一方，都能读取进程权限允许读取的文件。默认只绑定 loopback 降低了远程可达性，但那不是文件权限边界；以局域网模式暴露时影响更大。**已分发的 0.13.1 安装包确认带此缺陷**，用打包后的应用直接探测即复现。

## 修了什么

`backend/app_v2.py`：页面回退与文件下载分开。新增 `_page_file()`，解析请求路径后判断它是否仍落在页面目录内——只有解析后的真实路径能说明请求指向哪里；过滤字符 `../` 会放过同一逃逸的其他所有写法。目录之外、目录本身、非文件的路径一律交给页面路由处理，不作为下载。

`test_static_file_boundary.py`（新增）：九种逃逸写法 × 三个页面目录外的探针文件；合法静态资源、SPA 路由、未知 API 路径仍各自正确；带 Authorization 头也不会越界。另有一组直接针对判定规则的用例：页面目录内的软链接指向目录外时不得发送——请求里没有任何 `..`，只有解析后的落点能识别它。

`scripts/smoke_frozen.py`：每次冻结构建都对运行中的程序探测四种写法，探针用包内的 `VERSION`（无敏感内容）。**这一条对旧包会失败**，正是它的用途。

`test_version_contract.py`：补上 `AppVersion` 与 Windows 安装包文件名的校验。原合同只检查 `VersionInfoVersion`，所以文件名可能停留在上一个版本，让替换包与被替换的包无法区分。

## 不包含什么

审计报告 F02～F11 的修复正在 `feature/anchor-planning` 上开发，**不在本版**。本版相对 `v0.13.1-internal` 只有上述四个文件加一个新测试。
