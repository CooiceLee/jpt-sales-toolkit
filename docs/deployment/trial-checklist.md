# 团队试运行检查表

适用版本：`v0.11.7-internal`。

每个平台至少安排一名真实成员，并按顺序完成四个独立验收门。上一门未通过时，不把后续测试结果用于证明上一门可用。

## Gate A：纯净安装与本地程序

- [ ] 安装包内没有 XLSX、`.jptauth`、`.jptreq`、业务数据库或测试业务数据。
- [ ] 一键安装并启动，浏览器只访问本机 `127.0.0.1`。
- [ ] Leader 首次初始化并保存签发器口令和完整备份。
- [ ] 创建 Sales、Tech，完成 `.jptreq → .jptauth → 验证码 → 登录`。
- [ ] 创建测试记录，执行 `Exit JPT`、重启和覆盖升级，数据仍存在。
- [ ] 覆盖升级前自动生成并验证 `pre_upgrade` 备份；升级失败自动恢复，第二次启动不重复改写业务数据库。
- [ ] 卸载默认保留数据目录；备份恢复后数据库、附件和授权配置一致。

## Gate B：外部 XLSX 导入与更新

- [ ] Gate A 通过并完成导入前备份后，才取得并上传单独分发的 XLSX。
- [ ] 预检不写数据库；阻断项必须映射、修正或排除后才能提交。
- [ ] 正式提交完整写入；中途失败时整批回滚。
- [ ] 相同 `dataset_id + external_key` 重复导入执行更新，不产生重复记录。
- [ ] 修改文件后使用旧哈希提交会被拒绝。
- [ ] 导入后，计划到期页签与长期未跟进时间条件分别按正确口径返回结果和针对性空状态。
- [ ] 五类负责人业务地区均可筛选，`GLOBAL` 与“全部地区”不会混淆，组合条件取交集。
- [ ] 地图准确显示精确/近似/缺失状态；离线底图不阻塞列表和坐标修正。
- [ ] 各业务页按固定业务日期和阶段排序；缺失/无效日期排后，同值在刷新后顺序稳定。
- [ ] 只用不敏感测试地址验证外部地理编码；团队知道地址字段可能依次发送给高德和 Nominatim，底图会访问 CARTO/OpenStreetMap；界面显示实际候选服务商，Key 未进入截图、日志、仓库或安装包。
- [ ] Leader 客户模糊候选包含名称/别名与分数，合并前必须出现只读迁移预览。

## Gate C：账号映射与权限

- [ ] XLSX 不创建账号，未知、停用、歧义或角色错误的成员映射会阻断提交。
- [ ] Sales 只能查看自己负责或协作的客户和 Lead。
- [ ] Tech 只能查看自己的任务及关联数据，且看不到销售敏感字段。
- [ ] 同一成员换机重签后，旧授权记录变为历史。
- [ ] 错设备、错验证码、篡改文件和 91 天授权均被拒绝。
- [ ] 负责人账号业务地区准确，地区筛选不会按客户地址错误改写归属。

## Gate D：终端文件分发与同步

- [ ] Sales 使用 JSON 数据包导出自己的记录；XLSX 不作为终端同步协议。
- [ ] Leader 选择目标 Sales 后只导出其负责的 Lead；目标账号可导入，其他成员账号被拒绝。
- [ ] 导入后有主联系人的 Lead 仍指向正确联系人；无邮箱的多个姓名联系人没有被合并覆盖。
- [ ] Leader 导入前完成预检、权限过滤和快照，再执行合并。
- [ ] 重复导入同一数据包不重复创建客户、Lead、活动或任务。
- [ ] 本地新增活动与导入数据合并后均保留，冲突不会静默覆盖。
- [ ] JSON 只携带附件元数据，附件文件和完整备份另行传递。

反馈格式：测试模块、平台与版本、成员角色、测试编号、复现步骤、预期结果、实际结果、截图/日志路径、P0/P1/P2、是否阻塞下一 Gate。
