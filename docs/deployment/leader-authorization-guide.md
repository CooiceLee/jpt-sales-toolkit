# Leader 账号与设备授权指南

适用版本：`v0.11.8-internal`。

## 当前权限口径

- 全局角色只有 `Leader / Sales / Tech`。
- 每名成员同时只保留一条有效设备授权；换机由 Leader 用新 `.jptreq` 重签，旧授权自动转为历史记录。
- 每次授权固定 90 天，不能由界面或 API 延长；到期前 30 天提醒，7 天内显示紧急提醒。
- Tech 只读取分配给自己的售前/售后任务及关联客户、Lead；报价、金额、PO、输单原因等销售敏感字段不返回。
- 离职或设备丢失不依赖即时远程停用。Leader 本机停用会阻止后续签发或数据合并，但已经离线的旧设备不会被远程擦除。
- 每名 Leader / Sales / Tech 成员应配置一个负责人业务地区：`GLOBAL / 欧洲 / 北美/加拿大/澳洲 / 俄罗斯/土耳其/中东 / 东南亚`。`GLOBAL` 是全球业务归属，“全部地区”才表示不限制地区。

## 首位 Leader

全新安装第一次打开时选择“Set up a new team”：

1. 创建 Leader 用户名和登录密码。
2. 创建至少 12 位的签发器口令；该口令不写入数据库，也无法找回。
3. 系统在本机生成加密 Ed25519 私钥，并同时签发当前 Leader 设备的 90 天授权。
4. 立即执行一次完整备份，并把备份 ZIP 与签发器口令分开保存。

旧版本已有账号时，系统先处于 `Legacy migration mode`。现有 Leader 登录后在 Authorization Center 初始化签发器；系统会先为当前 Leader 建立设备授权，再关闭旧模式，不会留下“无授权回退登录”通道。

## 创建与签发成员

1. 在 Authorization Center 创建成员，角色只能选择 Leader、Sales 或 Tech。
2. 成员从自己的电脑导出 `.jptreq` 并发送给 Leader。
3. Leader 选择成员和请求文件，输入签发器口令，点击签发。
4. 将 `.jptauth` 文件发给成员；将页面显示的 16 位 Leader verification code 通过另一条可信渠道发送。
5. 成员导入文件、核对验证码并设置本地登录密码。

`.jptauth` 是设备和成员专属文件，不得上传 GitHub、群共享目录或公开工单。

## Excel 导入后的账号映射

- 使用 Leader 登录后进入 `Export / Import`，顶部选择 `Excel Import` 页签。JSON 终端交换、数据治理和客户合并各自位于独立页签，不与 Excel 导入混用。
- Excel 导入按四步向导执行：完整备份、选择 JPT-XLSX-1.0 工作簿、预检与修正、提交与验证。只有 `.xlsx` 文件可进入该流程。
- 预检报告限制在固定高度复核窗口中；成员映射、客户匹配、问题与排除项以折叠分组显示。数据较多时只在复核窗口或展开分组内部滚动，重新预检和正式提交按钮固定在窗口下方。
- 预检或提交进行中会锁定工作簿选择器和相关动作，旧请求不能覆盖后来选择的文件。预检断连可确认未写入；正式提交若断连或响应无法读取，结果属于“无法确认”，必须重新打开 JPT 并核对左侧计数和目标业务记录，不能立即重试。
- 若页面已经明确显示“导入完成”，但提示左侧计数刷新失败，说明提交结果已确认；不要重复导入，只需重新打开 JPT 加载最新计数。
- 先在 Authorization Center 创建并启用实际成员，再处理外部 XLSX；工作簿不能创建账号。
- 来源人员姓名、缩写或大小写变体由 Leader 映射到实际账号；无法唯一匹配时必须人工选择。
- 商机 owner 只能映射到 Leader 或 Sales；售前/售后任务 assignee 只能映射到 Tech。角色不符合时阻断提交。
- 映射确认后，分别使用 Sales 和 Tech 账号验证可见范围，不能只用 Leader 账号检查导入结果。
- XLSX 只负责外部数据摄取。成员终端之间的后续共享继续在 `JSON Exchange` 页签使用 JSON 数据包。

### Excel 四步操作明细

1. **完整备份**：在 Excel Import 页签先创建完整备份，记录备份文件名与时间。JSON 导出不能替代完整备份。
2. **选择工作簿**：只选择 `.xlsx`，确认文件名和数据集正确；预检后不要覆盖或重新保存该文件。
3. **运行预检**：预检只读，不写业务数据。依次展开成员映射、客户匹配、错误/警告与排除项；长清单只在固定复核区域内滚动。
4. **修正与复检**：把来源人员按职责映射到现有账号；确认客户复用或新建；只排除确认无效的记录。每次修改后执行“应用修正并重新预检”。
5. **提交**：只有页面明确显示可以导入、阻断项为零时，才执行“导入并合并”。记录批次号及新增、更新、归档、跳过、警告数量。
6. **验证**：核对左侧计数与目标业务记录；若提交响应中断且结果无法确认，不要立即重复导入，先重开程序查证。
7. **幂等与更新**：再次导入相同文件不得新增副本；更新文件必须保留原 `dataset_id` 和所有外部键。

## 业务地区、长期未跟进与地图

- 业务地区由 Lead 负责人账号决定，不按客户国家自动推断。地区、负责人、技术人员、搜索词和时间条件同时生效。
- 跟进页的“已逾期 / 今日到期 / 未来 7 天”判断 `next follow-up` 计划日期；没有计划日期的记录不会进入这些页签。
- 长期未跟进条件独立计算，日期优先级为“最近正式跟进 → 询盘日期 → 创建日期”。“从未正式跟进”只表示没有正式跟进活动，不代表没有询盘日期。
- 地图状态分为精确、近似、缺失。近似位置仅作地区参考；准备拜访、路线或距离判断前，应在坐标复核中补齐精确坐标。离线底图提示不代表业务数据丢失。
- 地址搜索与批量地理编码会把地址、城市、邮编和国家发送给一个或多个外部服务。默认为公共 Nominatim；高德显式启用后为首选，但空结果、网络、超时、配额或无效响应会回退 Nominatim，界面显示实际服务商。高德结果会转成统一 WGS84，高德不替换 CARTO/OpenStreetMap 底图。公共 Nominatim 只用于小规模、单终端、一次性查询；Key 不得进入前端、GitHub、安装包或日志，不允许外发的地址应人工录入经纬度或选点。
- Windows 从开始菜单启动时，变量必须写入受控的“当前用户环境”，随后退出 Windows 账号并重新登录；只在旧 PowerShell 窗口设置变量不会传给已经运行的 Explorer。macOS 从 Finder 启动时，变量必须由 `launchd`/MDM 为当前 GUI 会话注入，关闭 JPT 后重新启动；普通终端里的临时 `export` 不会传给 Finder。`v0.11.8-internal` 尚无 Key 输入界面，因此不具备上述管理条件时保持 Nominatim，不要把 Key 写进启动脚本或文档。
- 配置后只用不敏感测试地址验证界面显示的实际服务商和返回候选；若回退到 Nominatim 或出现 Key/权限错误，先停止提交真实客户地址并检查配置、权限和额度。鉴权错误不会自动回退。

## 客户模糊候选与安全合并

1. 只用 Leader 进入 Customer Merge。
2. 输入客户法律名称、品牌名、简称或历史名称；系统同时检索客户主名称和别名，并按相似度显示候选与分数。
3. 明确选择“来源客户”和“保留目标”。名称相似不代表一定是同一实体，应核对国家、域名、联系人和关联 Lead。
4. 等待只读迁移预览，核对将迁移的联系人、Lead、域名、别名与出差关联；预览不写数据。
5. 预览有效且目标正确后，只点击一次合并。来源客户会归档，关联数据迁移到目标客户，并保留审计记录。
6. 合并后重新搜索两个名称，检查目标客户及其别名、联系人和 Lead；若预览异常，不要执行合并。

## 续期、换机与恢复

- 普通成员：重新提交新 `.jptreq`，Leader 再签一次；Leader 目录中的旧授权记录转为历史。旧离线电脑不会即时收到撤销，仍可能使用至其本地 90 天授权到期。
- Leader 正常续期：在 Issuer Security 输入签发器口令，点击“Renew This Leader Device · 90 Days”。
- Leader 到期或从备份换机：启动页使用 Leader 用户名、登录密码和签发器口令三项完成本机恢复。
- 普通成员丢失设备：Leader 停用成员或等待其换机后重签；当前离线版本不承诺即时远程撤销。

## 备份边界

完整备份现在包含数据库、附件及 `data/config/`。其中包括 JWT secret、授权时钟和加密签发私钥，应按敏感文件保管。恢复到新 Leader 电脑后仍需执行 Leader 恢复，以重新绑定该设备。
