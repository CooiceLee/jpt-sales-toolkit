## Trip Planner v2 批次 1–5

| 批次 | 可用能力 | 验收结果 |
|---|---|---|
| 1 · 路线基础 | 中国出发与返回地点、硬日期窗、客户候选、自动顺序、手工拖动顺序、保存、重开和归档 | 路线不得越过开始/结束日期；保存后顺序和停靠保持，归档不删除历史 |
| 2 · 逐段交通 | 航班、自驾、公共交通、其他；优先级排序；每段改选、人工锁定和重新计算 | 每一段可独立确认；锁定段不会被自动顺序静默改写 |

| 4 · 半天与拜访准备 | 上午、下午、全天、停留天数、多地点拜访；客户人员、渠道代理公司陪同人员（如有）、JPT 内部参会人员、演示设备、PO 设备、访问主题和备注 | 日程按天/半天展示；三类参会人员分开保存和显示，一个客户可保留多个地点与各自准备内容，刷新后不丢失 |
| 5 · 正式导出 | XLSX、离线 HTML、ICS；兼容 Markdown 和 CSV | 五种文件与最后一次成功保存的路线一致；未保存修改、过期路线或越界路线不能直接生成正式文件 |

统一验收场景：上海出发并返回上海，2026-09-15 至 09-30，依次覆盖德国、法国和意大利。测试同时包含客户拜访、无客户自由停靠、同一客户多个地点、半天安排、逐段交通人工确认和完整拜访准备。

## 覆盖升级的数据保护

1. Leader/管理员先创建并验证完整备份，记录客户、Lead、任务、附件和授权基线。
2. 新版首次识别 v0.11.9 schema 3 后，在任何 schema 写入前创建 `pre_upgrade_schema3_to_schema6_...zip`。
3. `pre_upgrade` 必须通过 ZIP CRC、逐文件 SHA-256、SQLite 完整性、外键和行数清单验证后才开始迁移。
4. 迁移失败时恢复原数据库并停止启动；不得带错误进入业务页面。
5. 完成后核对客户、Lead、任务、Tech 任务包状态、附件哈希、授权配置和设备授权；第二次启动不得重复迁移或重复创建升级备份。
6. Windows 卸载后和 macOS 替换应用后，用户数据目录均须原位保留。

4. 真实 Windows 与 Apple Silicon 团队设备完成新装、覆盖升级、重启、数据保留和 Trip Planner 实测前，不得讨论 Stable / Latest。
