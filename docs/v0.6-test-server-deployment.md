# JPT Sales Toolkit v0.6 局域网测试服部署方案

## 目标

用一台局域网内电脑作为测试服务器，让团队成员通过浏览器访问同一个地址完成真实使用场景测试。

本方案优先验证：

- 多账号登录和权限边界。
- Leader 分配 Lead。
- Sales 跟进、成交、履约记录。
- Tech 售前/售后任务处理。
- Dashboard、地图、阶段卡片和数字统计一致性。
- 导入导出、附件、备份恢复等试运行能力。

## 推荐部署形态

- 部署方式：局域网 Web 测试服。
- 访问方式：`http://<测试服务器局域网IP>:8000`
- 服务端口：`8000`
- 数据目录：`data-test-server/`
- 数据库：`data-test-server/database.sqlite`
- 附件目录：`data-test-server/attachments/`
- 备份目录：`data-test-server/backups/`
- 回滚基线：`data/backups/rollback_v0.6_crud_baseline_20260504_023955.zip`

测试数据目录与当前开发数据目录 `data/` 隔离，避免团队测试污染本地开发基线。

## 一次性准备

### 零基础一键启动

macOS 推荐直接双击项目目录下的：

```text
Start JPT LAN Test Server.command
```

它会自动完成：

- 创建 `deploy/test-server.env`
- 检测局域网 IP
- 自动选择可用端口，优先使用 `8000`
- 初始化 `data-test-server/`
- 创建或刷新测试账号
- 创建一次启动前备份
- 启动局域网测试服务

启动后终端窗口会显示：

```text
Team URL: http://<你的局域网IP>:<端口>
```

把这个 `Team URL` 发给同一局域网内的测试成员即可。停止服务时，在该终端窗口按 `Ctrl+C`。

如果不想双击，也可以在终端执行：

```bash
cd /Users/liliang/Desktop/jpt-sales-toolkit
scripts/one_click_lan_test_server.sh
```

### 1. 复制测试环境配置

```bash
cp deploy/test-server.env.example deploy/test-server.env
```

编辑 `deploy/test-server.env`：

```text
JPT_DATA_DIR=/Users/liliang/Desktop/jpt-sales-toolkit/data-test-server
JPT_TEST_HOST=0.0.0.0
JPT_TEST_PORT=8000
JPT_PUBLIC_URL=http://<测试服务器局域网IP>:8000
```

局域网 IP 获取方式：

```bash
ipconfig getifaddr en0
```

如果电脑使用有线网络，可能需要改查其他网卡。

### 2. 安装依赖

```bash
python3 -m pip install -r requirements.txt
```

### 3. 初始化测试账号

```bash
python3 scripts/create_test_accounts.py --data-dir data-test-server
```

默认测试账号：

| 角色 | 账号 | 密码 | 说明 |
|---|---|---|---|
| Leader | `leader01` | `LeaderJPT2026` | 查看全部数据、分配负责人、管理权限 |
| Sales | `sales01` | `Sales01JPT2026` | 只处理自己相关 Lead |
| Sales | `sales02` | `Sales02JPT2026` | 只处理自己相关 Lead |
| Sales | `sales03` | `Sales03JPT2026` | 只处理自己相关 Lead |
| Tech | `tech01` | `Tech01JPT2026` | 处理技术任务 |
| Tech | `tech02` | `Tech02JPT2026` | 处理技术任务 |

脚本可重复执行。账号已存在时会更新角色、显示名、密码并重新启用。

## 启动测试服

```bash
scripts/start_test_server.sh deploy/test-server.env
```

启动后把 `JPT_PUBLIC_URL` 发给团队成员。

示例：

```text
http://192.168.1.25:8000
```

服务运行期间请保持测试服务器电脑开机，不要关闭终端窗口。

## 每日备份

手动备份：

```bash
python3 scripts/backup_test_server.py --data-dir data-test-server
```

备份文件会写入：

```text
data-test-server/backups/
```

保留策略：

- 保留最近 10 个备份。
- 保留最近 30 天内的备份。
- 取两者中更宽松的结果。

建议试运行期间每天测试结束后执行一次备份。

## 回滚方案

### 测试服数据回滚

测试服自己的备份在：

```text
data-test-server/backups/
```

恢复方式：

1. 停止测试服。
2. 选择一个 `backup_*.zip`。
3. 通过 Admin Restore 或 `AdminService.restore()` 恢复。
4. 重启测试服。

### 本地已验证基线

当前本地已验证基线备份为：

```text
data/backups/rollback_v0.6_crud_baseline_20260504_023955.zip
```

这个备份用于恢复当前 v0.6 CRUD 编辑闭环与 full regression 通过后的本地基线。

## 分发给团队前的检查清单

- `deploy/test-server.env` 中 `JPT_PUBLIC_URL` 已改为真实局域网 IP。
- `python3 scripts/create_test_accounts.py --data-dir data-test-server` 已执行。
- `scripts/start_test_server.sh deploy/test-server.env` 已启动。
- 管理员电脑可以访问 `http://127.0.0.1:8000`。
- 另一台局域网电脑可以访问 `http://<测试服务器IP>:8000`。
- 用 `leader01` 登录成功。
- 用 `sales01` 登录后只看到自己相关数据。
- 已执行一次 `python3 scripts/backup_test_server.py --data-dir data-test-server`。

## 已知边界

- 本方案只面向局域网，不面向公网。
- 当前是 HTTP，不是 HTTPS。
- 测试服务器关闭或休眠后，其他成员无法访问。
- 如果多人同时编辑同一条记录，后端会按 `row_version` 做冲突控制。
- 不建议在测试环境录入敏感客户隐私或正式合同文件。
